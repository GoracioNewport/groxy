# Развёртывание бота и наблюдаемости на бридже

Состояние на 07.09.2026. Готов и проверен на живом узле конвейер снимков;
интерактивная часть бота ещё пишется.

Всё живёт в репозитории `groxy` и выкатывается тем же `git pull` в
`/opt/groxy`, что и CLI. Отдельного репозитория, venv и пакетов из pip нет —
только стандартная библиотека Python.

## Что и где

| Что | Где |
|---|---|
| Модули | `/opt/groxy/bot/groxy_bot/` |
| Снапшоттер | `/opt/groxy/bot/bin/groxy-snapshot` |
| Юниты | `/opt/groxy/bot/systemd/` |
| Токен и список допущенных | `/etc/groxy/bot/` |
| База снимков | `/var/lib/groxy-bot/history.db` |

## Предпосылки

**Python 3.11 и новее.** На боевом бридже 3.11.2, `sqlite3` доступен модулем.
Отдельной утилиты `sqlite3` не нужно.

**`sudo` установлен.** Бот и снимок работают под пользователем `groxy-bot`, а
CLI требует root: файлы пиров лежат с правами 600, а `wg show` без root ничего
не показывает. На боевом бридже `sudo` есть. На тестовом `moscow-25000-01`
его нет — там снимок можно гонять только от root, и это не оплошность
установки, а состояние узла.

Обёртка сама решает, звать ли `sudo`: под root вызывает CLI напрямую. Поэтому
ручной запуск от root работает и на узле без `sudo`.

## Установка

### 1. Пользователь и каталоги

```
useradd --system --no-create-home --shell /usr/sbin/nologin groxy-bot
mkdir -p /var/lib/groxy-bot
chown groxy-bot:groxy-bot /var/lib/groxy-bot
```

### 2. Правило в sudoers

```
install -m 440 /opt/groxy/bot/systemd/groxy-bot.sudoers /etc/sudoers.d/groxy-bot
visudo -c -f /etc/sudoers.d/groxy-bot
```

Проверять обязательно: битый файл в `sudoers.d` ломает `sudo` целиком, включая
собственный вход администратора.

Правило перечисляет подкоманды поимённо, а не `bridge *`. Под звёздочку попали
бы `whitelist set-source` и `use-portal` — смена источника доменов и
переключение портала; боту первой итерации ни то, ни другое не нужно.

### 3. Токен и список допущенных

Токен кладёт владелец сам, значение в диалог не передаётся:

```
install -d -m 750 -o root -g groxy-bot /etc/groxy/bot
# дальше руками, интерактивно, чтобы значение не осело в истории шелла
```

Файл `token` должен быть доступен боту на чтение:

```
chown root:groxy-bot /etc/groxy/bot/token
chmod 640 /etc/groxy/bot/token
```

Список допущенных — `/etc/groxy/bot/allowed-chat-ids`, по одному числу на
строку, `#` начинает комментарий. Пустой список считается ошибкой, а не
«пускать всех»: бот выдаёт и отзывает доступ к VPN, и файл, опустевший из-за
неудачной правки, не должен молча открыть его кому угодно.

### 4. Снимки

```
install -m 644 /opt/groxy/bot/systemd/groxy-snapshot.service /etc/systemd/system/
install -m 644 /opt/groxy/bot/systemd/groxy-snapshot.timer   /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now groxy-snapshot.timer
```

Проверка, что снимок пошёл:

```
systemctl start groxy-snapshot.service
journalctl -u groxy-snapshot -n 20 --no-pager
```

Снапшоттеру токен не нужен — он читает только `load_paths()`. Поэтому снимки
можно включать раньше, чем заведён бот, и программа, не держащая секрета, не
может уронить его в журнал.

## Что уже проверено на живом узле

Прогон на `moscow-25000-01` 07.09:

- снимок читает состояние через `groxy bridge stats --json`, собирает нагрузку,
  память и диск и пишет связную строку в `peer_samples` и `node_samples`;
- второй прогон обновляет `peer_totals`, накопление поверх счётчиков ядра
  работает;
- база создаётся с правами 600 — в ней endpoint'ы клиентов, то есть адреса, с
  которых люди подключались;
- `systemd-analyze verify` на юните проходит без замечаний;
- под пользователем без `sudo` снимок отказывается внятной строкой
  «не удалось запустить /usr/bin/sudo», а не стеком на пол-экрана.

Не проверено на живом узле: работа таймера под `groxy-bot` — на тестовом узле
нет `sudo`, а на боевом юнит пока не ставился.

## Порядок первого запуска на боевом бридже

Снимки можно включать сразу: они только читают и пишут в свою базу, клиентов
не задевают вовсе. Ставить их стоит **до** бота, чтобы к моменту первых
вопросов «а что было ночью» история уже набралась.

Бот включается после того, как положен токен и заполнен список допущенных.
