## Главный результат: per-client учёт для обычного WireGuard-клиента

Гипотеза, которую стоило проверить первой: AmneziaWG допускает нейтральные
параметры обфускации (`ValidateObfuscation` разрешает `H1–H4` от нуля и нулевые
джиттеры), а в таком виде AWG протокольно совпадает с обычным WireGuard.

Проверено — работает. AWG-инбаунд с `jc/jmin/jmax = 0`, `s1–s4 = 0`,
`h1–h4 = 1,2,3,4`, без header protection, принял **ядерного WireGuard-клиента**
без единой правки на его стороне:

```
peer: 4Cu7Ve4pTwicYzjY6Pt5UUggdkrDtHkimVEppG5iajk=
  latest handshake: 23 seconds ago
  transfer: 476 B received, 564 B sent
```

И при этом панель считает трафик **по клиенту**. После загрузки 10 МБ через
туннель `GET /panel/api/clients/traffic/stand-awg-1` вернул:

```json
{"email":"stand-awg-1","up":1558,"down":10486678,"lastOnline":1788339437007}
```

`down` совпадает с размером файла байт в байт.

Это снимает главный размен всей схемы. В `STAND-3XUI-RESULTS.md` он записан так:
«нативный WG-клиент = нет per-client учёта/квот в панели», и из него росли
варианты «смириться» либо «увести клиентов на Reality». Ни то, ни другое больше
не нужно: тупой WG-клиент на роутере и полноценный per-client учёт с квотами
совместимы, если инбаунд объявлен как `amneziawg` с нейтральной обфускацией.

Побочно это же даёт путь наращивания: обфускацию на том же инбаунде можно
включить позже для тех клиентов, кто умеет AWG, не трогая остальных.

## Как это устроено внутри

Панель разворачивает AWG-инбаунд в пару «встроенный интерфейс + SOCKS-инбаунд»:

```
amneziawgnet: started embedded interface awg1 for inbound 1
```

В сгенерированном `bin/config.json` появляется:

```
tag = in-51830-udp, protocol = socks, listen = 127.0.0.1:65101
  accounts: [{user: "stand-awg-1", pass: <генерируется панелью>}]
  sniffing: enabled, destOverride = [http, tls, quic, fakedns]
```

То есть gVisor-netstack декапсулирует WG и отдаёт трафик в SOCKS-инбаунд Xray,
где **на каждого клиента заведён отдельный аккаунт** — отсюда и per-client
счётчики (`user>>>email>>>traffic`). Ядерного интерфейса нет вообще: UDP-порт
51830 слушает сам процесс `x-ui`.

Важное следствие: **sniffing на этом инбаунде включён из коробки**, значит
доменный carve-out для AWG-клиентов доступен сразу, без ручной правки конфига.
Это ровно тот механизм, ради которого затевался переход с ipset-схемы v1.

## Что ещё выяснилось на этом же прогоне

| Проверка | Результат |
|---|---|
| TCP наружу через туннель | работает, exit-IP `193.233.246.86` (сам bridge) |
| UDP наружу | работает (DNS-запрос на `1.1.1.1` резолвится) |

### DNS на адресе шлюза — проблема для Фазы C

Встроенный путь не поднимает DNS-ответчик на адресе сервера в туннеле.
Запрос на `10.99.0.1:53` уходит в netstack и умирает по таймауту.

В v1 у всех 36 клиентов в `.conf` зашито `DNS = 10.66.66.1` — адрес dnsmasq на
бридже. Критерий Фазы C («старый клиентский `.conf` работает против панели без
правок») из-за этого под угрозой: handshake и трафик поднимутся, а имена
перестанут резолвиться.

Варианты, которые надо проверить в Фазе C:
1. Правило `port 53 → dns-out` в роутинге панели — на ручном стенде такой
   перехват работал (`STAND-3XUI-RESULTS.md`), но там был инбаунд `wireguard` с
   конфигом, написанным руками. Здесь запрос до Xray, похоже, вообще не доходит.
2. Оставить на бридже работающий dnsmasq и дать ему адрес, который клиенты уже
   знают, а AWG-инбаунду выделить другую подсеть.
3. Сменить DNS в клиентских конфигах — ломает критерий «без правок», годится
   только как запасной путь.

### ICMP

Пинг наружу из туннеля не проходит. Для боевых клиентов это заметная деталь:
диагностика вида «пингани 8.8.8.8» перестанет работать, хотя интернет будет
жив. В v1 с ядерным WG пинг проходил. Отдельного решения не требует, но
пользователей это путает — стоит помнить при переводе прода.

### Скорость

1,6 МБ/с в один поток — первая цифра, а не замер. Канал nether→moscow, RTT
47 мс, один TCP-поток, внешний speedtest-хост. Полноценный замер под требование
по сквозному throughput остаётся в списке Фазы B: нужен многопоточный прогон и
сравнение с ядерным WG на том же маршруте, иначе непонятно, сколько стоит gVisor.
